# Smart Ticket Triage

AI-powered IT support ticket triage system that classifies, routes, and auto-replies to tickets — with **human-in-the-loop guardrails** at every step. The LLM proposes; deterministic code decides.

## Architecture Overview

```
┌──────────────────────────────┐
│  web (Next.js)               │
│  Submit · Queue · Review     │
│  Dashboard · KB Management   │
└──────────────┬───────────────┘
               │ REST (JWT, RBAC)
┌──────────────▼───────────────┐
│  core-api (Django + Ninja)   │  ← source of truth
│  Masking · Trust Scorer      │
│  Switch Router · HITL Queue  │
│  Incident Detector · Audit   │
└──────┬───────────────┬───────┘
       │ Celery         │
┌──────▼──────┐  ┌──────▼──────┐
│  ai-engine  │  │  PostgreSQL │
│  FastAPI +  │  │  + pgvector │
│  LangGraph  │  └─────────────┘
└─────────────┘
```

The system is split into **three services** with strict permission boundaries:

| Service | Stack | Role |
|---------|-------|------|
| **core-api** | Django · Django Ninja · Celery | Business logic, routing decisions, HITL queue, audit log |
| **ai-engine** | FastAPI · LangGraph | Hybrid retrieval (BM25 + vector), reranking, LLM inference. **Read-only DB access** — no authority to write business data or make routing decisions |
| **web** | Next.js | Employee ticket submission, technician review queue, dashboards, KB management |

Supporting infrastructure:

| Component | Purpose |
|-----------|---------|
| **PostgreSQL + pgvector** | Relational data, vector embeddings (HNSW), full-text search |
| **Redis** | Celery broker & result backend |
| **Ollama** | Local LLM for PII masking & cloud fallback |

## Key Design Principles

- **LLM proposes, code decides.** Every field generated by the LLM carries a `proposed_` prefix. The deterministic [Switch Router](services/core-api/apps/tickets/services/) makes all routing decisions as a pure function — no I/O, fully testable.
- **Trust Score over self-confidence.** LLM self-confidence is logged but **never** used for routing. A calibrated logistic regression model scores proposals based on verifiable retrieval & generation signals.
- **Fail towards humans.** When anything degrades — LLM timeout, masking failure, low retrieval score — tickets go to the HITL queue, never to auto-reply.
- **KB-level authority.** Auto-reply permission lives on the KB article metadata (`auto_reply_allowed`), set by humans. The model cannot grant itself permission.
- **Shadow mode first.** The router runs in shadow mode initially, logging decisions without acting, to collect calibration data with zero risk.

## Prerequisites

- **Python 3.13+**
- **Node.js 18+** (for the web frontend)
- **Docker & Docker Compose**
- **[uv](https://docs.astral.sh/uv/)** — Python package manager (manages the workspace)
- **[Ollama](https://ollama.ai/)** — Local LLM runtime (runs on host, not in Docker)

### Ollama Models

Pull the required models before starting:

```bash
ollama pull qwen3.5:9b    # inference
ollama pull bge-m3         # embeddings
```

## Getting Started

### 1. Clone & configure environment

```bash
git clone <repo-url> && cd smart-triage
cp infra/.env.example infra/.env
# Edit infra/.env — at minimum, change SECRET_KEY and PII_ENCRYPTION_KEY for non-dev use
```

### 2. Start infrastructure with Docker Compose

```bash
cd infra
docker compose up -d
```

This starts all services:

| Service | Port | Description |
|---------|------|-------------|
| `core-api` | `localhost:8000` | Django REST API |
| `ai-engine` | `localhost:8001` | FastAPI AI inference |
| `web` | `localhost:3000` | Next.js frontend |
| `db` | `localhost:5434` | PostgreSQL + pgvector |
| `redis` | `localhost:6380` | Redis (Celery broker) |
| `worker` | — | Celery worker |
| `beat` | — | Celery beat scheduler |

> **Note:** PostgreSQL is exposed on port **5434** (not 5432) to avoid clashing with any locally-running Postgres instances.

### 3. Local development (without Docker)

For iterating on individual services outside Docker:

```bash
# Install all workspace packages
uv sync

# Core API
uv run --package core-api python services/core-api/manage.py runserver

# AI Engine
uv run --package ai-engine uvicorn ai_engine.main:app --port 8001 --reload

# Web
cd services/web && npm install && npm run dev
```

## Configuration

### Thresholds

All routing thresholds, budget limits, and alert parameters are centralized in a single YAML file — **no magic numbers in code**:

```
services/core-api/config/thresholds.yaml
```

Key thresholds include:

| Parameter | Default | Purpose |
|-----------|---------|---------|
| `t_auto` | 0.88 | Trust score minimum for auto-reply (precision ≥ 0.95) |
| `t_route` | 0.72 | Trust score minimum for auto-route (precision ≥ 0.85) |
| `retrieval.floor` | 0.45 | Cross-encoder score below which LLM is not called |
| `budget.daily_cost_ceiling_usd` | 50 | Daily spend cap — exceeding shuts off AI entirely |

Values marked with 🔧 in the config are **initial assumptions** awaiting calibration from shadow mode data.

### Environment Variables

See [`infra/.env.example`](infra/.env.example) for all available configuration. Key variables:

| Variable | Description |
|----------|-------------|
| `SHADOW_MODE` | `true` (default) — router logs decisions without acting |
| `EMBEDDING_PROVIDER` | `ollama` or `stub` (deterministic, for CI) |
| `RERANKER_PROVIDER` | `lexical` (default, offline) or `cross_encoder` |
| `PII_ENCRYPTION_KEY` | Base64-encoded 32-byte AES-GCM key for PII quarantine |

The evaluation suite runs against a golden set of 150–300 hand-labeled tickets:

```bash
# Run eval suites
uv run pytest evals/suites/ -q --json-report

# Compare against baseline
uv run python evals/report.py --compare evals/baselines/baseline.json
```

**CI Gate** — every PR must pass eval thresholds before merge:

| Suite | Metric | Threshold |
|-------|--------|-----------|
| Retrieval | Recall@5 | ≥ 0.90 |
| Classification | F1 per category | ≥ 0.85 (each) |
| Quote validation | Hallucination catch precision | ≥ 0.95 |
| Refusal | Out-of-KB refusal rate | ≥ 0.90 |
| Injection | Detection recall | ≥ 0.95 |
| End-to-end | Auto-reply precision | ≥ 0.95 |

## Ticket Processing Pipeline

```
Ticket submitted
    │
    ▼
PII Masking (regex → Ollama NER)
    │  critical PII → BLOCK
    │  mask failed  → HITL
    ▼
Incident Detection (duplicate vs mass incident)
    │  mass incident → ESCALATE
    ▼
AI Engine (via Celery)
    ├─ Injection detection
    ├─ Hybrid retrieval (BM25 + vector → RRF)
    ├─ Cross-encoder reranking
    │    └─ below floor → refuse (skip LLM)
    ├─ Few-shot selection
    ├─ LLM inference (JSON schema output)
    └─ Validation (quote match + negation check)
    │
    ▼
Trust Scoring (logistic regression, calibrated)
    │
    ▼
Switch Router (pure function, deterministic)
    ├─ auto_reply  → send KB-based answer
    ├─ auto_route  → assign to team
    ├─ hitl        → human review queue
    ├─ block       → security alert
    └─ escalate    → incident management
```

## Architecture Decision Records

| ADR | Decision |
|-----|----------|
| [0001](docs/adr/0001-code-level-routing.md) | Routing by code, not by prompt |
| [0002](docs/adr/0002-kb-level-autoreply-authority.md) | Auto-reply authority lives on KB metadata |
| [0003](docs/adr/0003-reject-llm-self-confidence.md) | LLM self-confidence excluded from routing |
| [0004](docs/adr/0004-split-ai-engine.md) | AI engine as a separate service with read-only DB |
| [0005](docs/adr/0005-threshold-on-cross-encoder-not-fused-score.md) | Thresholds on cross-encoder scores, not fused scores |
| [0006](docs/adr/0006-runbook-always-hitl.md) | Runbook execution always requires HITL approval |

## Rollout Phases

| Phase | Milestone | Gate |
|-------|-----------|------|
| **P0** | Contracts, DB, masking, audit, golden set, CI | Eval in CI, masking 100% coverage |
| **P1** | Full AI graph, router (shadow mode), HITL queue | 500+ shadow data pairs |
| **P2** | Calibrate trust score, set T_auto/T_route | Auto-reply precision ≥ 0.95 on holdout |
| **P3** | Enable auto-route | Reroute rate < 15% for 2 weeks |
| **P4** | Enable auto-reply (3–5 low-risk KB articles) | Reopen rate < 5% for 1 month |
| **P5** | Runbook (via HITL), few-shot pool, expand KB whitelist | Per-batch reopen threshold |
